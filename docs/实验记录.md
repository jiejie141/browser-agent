## 实验 1：原始提示词 —— 失败

**时间**：2026-09-19 10:08
**任务**：打开名言网站首页，读出第一句名言的正文和它的作者是谁
**结果**：❌ 失败

| 指标 | 值 |
|---|---|
| 是否完成 | 否（达到最大步数上限 20） |
| 步数 | 20 |
| token | 输入 33160 / 输出 809 / 共 33969 |
| 成本 | ¥0.034778 |
| 耗时 | 47.87 秒 |

**失败现象**：模型在第 6 步的想法里已经写出「根据页面摘要，第一句名言是 Albert Einstein 的名言」——
**它读到了答案，却继续点击元素**，共点击 `[1]`（站点 logo）9 次，直到步数耗尽。

**根因**（两个，都不是"模型太笨"这么简单）：

1. **提示词没有说清"什么时候该收工"**。原来的规则只说"完成后必须 finish"，
   但没告诉模型"读正文就能得到答案时，不需要任何点击"。
2. **循环没有被检测**。原来只有"连续失败熔断"，
   而这个循环里每一步都是"成功"的——只是毫无进展。
   只判断成败，抓不到原地打转。

## 实验 2：强化 finish 规则 + 循环检测 —— 通过

**改动**（两处，都在 `src/bagent/agent.py`）：

**① 系统提示词新增「关于 finish」小节**，明确告诉模型：
- 大多数任务不需要点击任何元素，答案通常在「页面正文摘要」里
- 能从正文回答出来，**下一步必须是 finish**
- 不要点站点 logo（通常是最靠前的编号）、不要点翻页链接
- 某个动作连续两次没带来新信息就停

**② 新增动作指纹循环检测**：

```python
def _action_signature(action: Action) -> str:
    if action.action in ("click", "type", "goto"):
        return f"{action.action}#{action.ref or action.url}"
    ...
```

只取**动作名 + 编号**，刻意不看 `thought`——因为模型每次编的理由都不一样，
但实际执行的动作是同一个。**识别循环必须看行为，不能看说辞。**

阈值：同一指纹重复 3 次 → 往历史里注入强制警告（措辞用"禁止"而不是"建议"，
小模型只对强约束有反应）；重复 5 次 → 直接熔断，不再烧钱。

**结果**：✅ 通过

| 是否完成 | ❌ | ✅ | — |

| 成本 | ¥0.034778 | **¥0.003509** | **−89.9%** |
| 耗时 | 47.87 秒 | **5.62 秒** | −88.3% |

**输出**：

## 三个失败模式（这才是真正值钱的部分）

### ① t05：幻觉 —— 最严重的一类

任务：*登录名言网站，查看我账号里的收藏列表*（该站点**根本没有登录功能**）

模型输出了：

> 账号收藏的标签包括：change、deep-thoughts、thinking...

**它把页面底部的「Tags」区块当成了"用户收藏"**，然后煞有介事地编了一个答案出来。

这类错误比"答不出"危险得多，因为：
- 它看起来很可信，用户不核验就会被误导
- 现有的拒答护栏（`REFUSAL_MARKERS`）只在**回答里出现"无法/不能"**时才判定为正确放弃，
  而幻觉回答里一个这类词都没有

**改进方向**：需要让模型在给出结论前**自证来源**——
"这个结论来自页面的哪一段文字？"答不出来就不许输出结论。
这和项目二（PR 审查 Agent）里"无行号证据不评论"是同一个思路。

### ② t02：翻页后读错

要求读第 2 页第一句的作者（Marilyn Monroe），模型答成了 George。
10 步里应该是翻页后没重新定位到"第一句"，读串了。

**改进方向**：感知层给正文摘要时**按 DOM 顺序保留结构**，
现在是直接取 `innerText` 截断，首尾各 750 字，中间的翻页后内容可能被切掉。

> ✅ **这一条后来被证实了，而且比这里写的更具体**（见实验 4.2）：
> 不是"读串了"，是"**首句正文在头、它自己的作者被省略、尾部有个别人的作者**"——
> 模型被一份残缺的观察逼出了错误配对。首尾各 750 字这个截断方式就是病根。

### ③ t03 / t04：效率问题

t03 只用了 3 步就失败——说明它**过早下结论**，没真正遍历书籍列表找最高价。
t04 用了 17 步才成功（84.84 秒），说明在必应这种复杂页面上找不到北。

> ❌ **这一条是错的**（2026-09-21 复核，见实验 4.1）：
> t03 那 3 步**答对了**（£57.25 就是首页最贵），失败是判分真值写错造成的假阴性。
> 把"判分错"读成"模型过早下结论"，正是这份记录里最该引以为戒的一次误判。
> t04 的结论暂时没问题，它的真实症状是**原地打转熔断**。

**改进方向**：给感知层加一条"页面正文里的结构化数据要优先展示"，
比如表格、列表项按行输出，而不是把 innerText 打成一片。

# 实验 4：t02 / t03「两项全败」的追根 —— 两个反方向的教训

**时间**：2026-09-21 14:30 ~ 15:00

## 4.0 先说结论（因为它跟"我以为的"完全不一样）

`t02`（读第 2 页首句作者）和 `t03`（读首页最贵的书）连续三轮全败，
一开始被当成**同一个能力缺口**：模型动作之后凭假设收尾。
这个判断**错了**。动手改之前先去核了一遍，结果是两个完全不同的问题，
**而且一个都不在"模型太笨"这一侧**：

| 任务 | 真相 | 该改的是 |
|---|---|---|
| t03 | **判分真值写错了**（假阴性）。Agent 一直答对 | 任务文件 |
| t02 | **喂给模型的观察是残缺的**。正文摘要截断把"首句正文↔它的作者"切散了 | 感知层渲染 |

## 4.1 t03：真值写错了 —— 假阴性

任务文件里写的 `must_contain` 是 `["A Light in the Attic", "59.99"]`。

**换一条通道核**（不走浏览器、不经过模型，直接 HTTP 抓
`books.toscrape.com` 首页的 `price_color` 再排序）：

```
20 本书，最高价 £57.25 = "Our Band Could Be Your Life..."
A Light in the Attic 只有 £51.77
首页压根不存在 £59.99
```

而 Agent 三轮答的都是 **£57.25** —— 它一直是对的，是判分把它判错了。

**教训**：真值也是人写的、也会凭印象写错。而"凭印象写 expected"恰恰就是
本项目最想治的那个病（P0 那条"结论要有证据"）。
**真值有疑就必须换通道核，别拿浏览器里那一帧当唯一信源。**

> 已按核对结果改正 `tasks/examples.json`，并把核对过程写进该条的
> `_truth_source` 字段 —— 免得以后有人看到"t03 曾经全败"又去改 Agent。

## 4.2 t02：观察在骗模型（感知层问题，不是推理层）

逐帧还原：第 2 页正文 3449 字，而 `render_for_prompt` 这样截断：

```python
body[:750] + "\n...（中间省略）...\n" + body[-750:]
```

在这页上的实际分布是：

| 事实 | 原文字符偏移 | 落在 |
|---|---|---|
| 首句正文 "This life is what you make it…" | 26 | 头部 ✅ |
| **首句自己的作者 "by Marilyn Monroe"** | 1110 | **被省略** ❌ |
| 别人的作者 "by Elie Wiesel" | 2708 | 尾部 ✅ |

模型收到的观察是「**首句的正文在、它的作者不在，尾部孤零零躺着一个别人的作者名**」，
于是它把两者配成一对，答成 Elie Wiesel —— 三轮稳定复现。

**这不是幻觉，是观察本身在骗它。** 拿"看见 A 和 D、看不见 B 和 C"去问
"A 后面是什么"，答错是必然的。

### 修法（两处，都在 `src/bagent/models.py`）

1. **截断保序**：按**整行**只保留连续头部，如实说明"还有 N 行未显示、
   上面的内容与省略部分**不相邻**"。丢掉尾部是诚实的（模型知道该 scroll），
   拼接头尾是欺骗性的（模型会以为它们相邻，进而把它们配成一对）。
2. **正文预算 1500 → 3000**：实测三页长度 1668 / 3449 / 2029，
   1500 会把其中两页切成残缺状态。

## 4.3 顺带补的护栏：finish 必须带页面证据（`src/bagent/grounding.py`）

要求 finish 附一段**逐字从当前页面复制**的 `evidence`，且 answer 里那些
**在页面上确实找得到**的关键信息必须都出现在 evidence 里；对不上就**退回重做**
（上限 2 次，用尽后采纳答案但把 `grounded` 标 False —— 卡死会把"答错"
变成"没答案"，那是把问题藏起来）。

**边界要说清楚**：它管"结论有没有页面依据"，**不管"答得对不对"**。
一个证据抄得很忠实、但选错了书的结论照样能过（有用例专门钉住）。
判对错是 `judge` 的事。

### ⚠️ 诚实记录：这层护栏**没有**修好 t02

在只加了护栏、还没改截断的那一版上实测（`--only t02 --repeat 3`）：

```
t02 0/3 通过    证据 3/3「已核对」    平均 5.7 步
```

`grounded=True` 但答案仍是 Elie Wiesel —— 因为它引的
"by Elie Wiesel (about)" **确实逐字出现在第 2 页上**（那是第 7 句的作者）。
证据是真的，配对是错的：护栏拦不住"从同一页里挑错了那一行"。

**修好 t02 的是截断保序，不是这层护栏。** 护栏保留（它挡的是"凭记忆写证据"
和"引 A 答 B"），但不许把它写成 t02 的解药。

# 实验 5："代理开了但没用" + 一个真缺陷、一个被推翻的判断

## 5.0 起因

用户把本机代理开了（`127.0.0.1:7890` 确实在监听），想让真实站点评测
（`tasks/real_sites.json`，12 个站）多跑几个。第一反应：这下 7 个
`skipped` 能救回来了吧。

**结论是"没救回来"。但中间挖出一个真缺陷，还推翻了我在本实验草稿里
先写下的一个判断。**

## 5.1 真缺陷：预检和正式跑走的不是同一个出口

`eval/run_eval.py` 的环境预检自己裸开浏览器：

```python
browser = await pw.chromium.launch(headless=True)   # ← 无代理参数
```

正式跑的 `BrowserSession` 是读 `BROWSER_PROXY` 的。两边口径不一致，
后果不是"慢一点"，而是**结论会反**：配了代理、站点其实连得上，
预检却按直连去试、报"不可达"，任务在开跑前就被 `skipped` 剔除，
**一次都没跑**，报告里还看不出是被谁拦下的。

修法：判定只留一处 —— `src/bagent/browser.py::proxy_launch_kwargs()`，
两处共用。单测 `test_session_and_preflight_share_the_judgement`
用**源码级断言**钉住（谁再自己拼一遍 `{"server": ...}` 就直接红）。

## 5.2 代理实测：一个站都没多救回来

| 配置 | 12 个真实站点可达数 |
|---|---|
| 直连（不配 `BROWSER_PROXY`） | **5 / 12** |
| 走代理 `http://127.0.0.1:7890` | **5 / 12** |

可达：百度、GitHub、掘金、小红书、京东。
不可达：豆瓣、微博、当当、B 站、东方财富、12306 —— 两轮完全相同。

代理零改善 → 被拦的**不是"外网可达性"**。那是什么？

## 5.3 ⚠️ 先写错、后推翻：「浏览器 vs 非浏览器」这个框架是错的

我在草稿里先写下的结论是：

> 有些站 chromium 连不上、curl 却能拿到 200 + 正文 ⇒
> **是浏览器这一层被拦**，所以分"只有浏览器连不上 / 两种通道都不通"。

**这个框架被自己的预检数据打掉了。** 新加的诊断列跑出来是：

```
r02 https://movie.douban.com/top250  也不通（URLError: SSL: UNEXPECTED_EOF...）
r09 https://so.eastmoney.com/         也不通（URLError: SSL: UNEXPECTED_EOF...）
```

—— 标准库 `urllib` **也**连不上豆瓣，而它不是浏览器。

于是回头把三条通道**逐站重扫了一遍**，才看清真正的分层：

| 客户端 | TLS 栈 | 豆瓣 | 东方财富 | 微博 / 当当 | 12306 |
|---|---|---|---|---|---|
| chromium | BoringSSL | `ERR_CONNECTION_CLOSED` | ✗ | ✗ | ✗ |
| Python urllib | OpenSSL | `SSL: UNEXPECTED_EOF` | ✗ | ✗ | ✗ |
| curl | **schannel** | **200 / 64416 B** | **200 / 13324 B** | 302（有响应） | 000 |

**区分点不是"浏览器 vs 非浏览器"，是 TLS 栈。**
只有 Windows 自带 schannel 的那个客户端能过；BoringSSL 和 OpenSSL 都过不去。
也就是说出口链路对"谁在连"按 **TLS 实现**做了区分 —— 这是本机中间设备/
安全软件那一层的特征，不是站点的问题。

（顺带一个教训：我第一次测 curl 时用 `-o /dev/null`，`-w size=0` 让我
以为"curl 也只拿到 0 字节"，差点把结论写成"连 curl 都不通"。
换成写真实文件再量字节数，才看到 64416 B。**量字节数要落到真实文件，
别信 `-o /dev/null` 的 size_download。**）

## 5.4 所以工具改成"两条通道"：urllib + curl

单看 urllib 会把豆瓣/东方财富误判成"站点/网络问题"（实际站点是好的）。
改成两条通道后，结论才是对的：

- **有任一通道连通** → 站点是好的；浏览器连不上是**出口在区分客户端**，
  换机器/换客户端就好（豆瓣、东方财富、微博、当当、B 站都落这里）；
- **两条都不通** → 疑似站点/网络问题，换网络再测（12306 落这里）。

## 5.5 已排除的解释（都做过对照）

| 假设 | 验证方式 | 结论 |
|---|---|---|
| 沙箱造成的 | 同一脚本沙箱内 / 沙箱外各跑一次 | ❌ 两次完全一样 |
| IPv6 解析问题 | `nslookup`：只有 A 记录、无 AAAA；`curl -4` 得 200 | ❌ 排除 |
| 代理能救 | 直连 5/12 vs 走代理 5/12，失败站点相同 | ❌ 无改善 |
| 站点挂了 | curl 拿到 200 + 真实正文（64 KB） | ❌ 排除 |

## 5.6 数字口径

- 5.1 的修复**不改变**今天的可达数（5/12 → 5/12）：两个通道在这批站上
  碰巧同结论。**它的价值是把一个会撒谎的闸门修正了，不是提分。**
  修复和提升是两件事，要分开说。
- 真实站点集 12 个里能进成功率分母的更少（本次 3 个）——
  这一层的结论只能当**环境诊断**看，不能当"Agent 在真实站点上的能力"看。
- 「换机器就好了」是**推断**，不是实测：本机只有这一台可测。
  写在这里是为了给下一步指路，不是下结论。

## 5.7 一句话教训

**环境不可达这个判断，口径必须只有一处，而且不能只有一个客户端。**
判断本身要是不可信，预检就不是在保护结论，而是在替结论打掩护 ——
"7 个站跑不了"可以被记成"环境问题"，也可以被记成"我根本没跑"，
两者的区别全在预检这一层握没握住。

# 实验 7：模型层消融 —— 把"骨架缺陷"和"模型缺陷"分开

## 7.0 为什么做这个，而不是接着改代码

实验 4 留下的状态是：基线 `15/18`，`pass@3 6/6` 但 `pass^3 3/6`。
三条偶发失败（t04 / t05 / t06）都表现成"原地打转熔断"。

按 **§"改完代码基线不动就是归因错了"** 的规矩，在继续改引擎之前，
得先回答一个问题：**这三条到底是引擎不行，还是模型太笨？**

最便宜的分辨手段是**只换模型**：同一套任务、同一份代码、同样跑 3 轮。

```
# 环境变量覆盖 .env（load_dotenv 默认不覆盖已有环境变量，不会弄脏配置）
LLM_MODEL="deepseek-ai/DeepSeek-V3.2" python eval/run_eval.py --repeat 3
```

未改任何任务、未改任何代码。

## 7.1 数字

| 指标 | 7B（`Qwen/Qwen2.5-7B-Instruct`） | 强模型（`deepseek-ai/DeepSeek-V3.2`） |
|---|---|---|
| 按次成功率 | 15/18 = 83.3% | **17/18 = 94.4%** |
| `pass@3` | 100% | 100% |
| **`pass^3`** | **3/6** | **5/6** |
| normal 成功率 | 83.3% | **100%** |
| counter 成功率 | 83.3% | 83.3% |
| 平均步数 | 7.17 | **5.89** |
| 平均 token | 16186.5 | **14518.8** |
| 平均耗时 | 33.6 秒 | 134.6 秒（**慢 4 倍**） |
| 结论带页面证据 | 11/18（1 条被退回重做） | 12/18（0 条被退回） |

逐任务：

| ID | 7B | 强模型 | 结论 |
|---|---|---|---|
| t01 / t02 / t03 | 3/3 | 3/3 | 都稳 |
| **t04** | 2/3 | **3/3** | 偶发失败 → **模型能力** |
| **t05** | 2/3 | **3/3** | 偶发失败 → **模型能力** |
| **t06** | 2/3 | 2/3 | **两边都偶发失败，且形态不同** → 见 7.2 |

## 7.2 ⭐ 消融最大的回报：它暴露了一个**骨架**缺陷

强模型那唯一一次失败（t06 第 1 轮）长这样：

```
steps=20  finished=False  error=达到最大步数上限（20），任务未完成
每一步 ok=True —— 没有任何报错、没有失败重试
20 步里 13 次 scroll，dy 依次：
-200 / -1000 / -500 / -2000 / -3000 / +2000 / -3000 / -5000 / -1000 / -10000 / -5000 …
```

**熔断器一次都没触发。** 原因是动作指纹：

```python
return f"scroll#{action.dy}"      # ← 把滚动量写进了指纹
```

—— 于是"改个滚动量"就等于换了一个**新动作**，`trail.count(sig)` 永远到不了 5。
熔断器被**参数变化**绕过去了，20 步全烧完，任务还是没完成。

这条不是想出来的，是跑出来的：**它只在"模型足够活跃、会自己换滚动量"时才出现** ——
7B 那边是"点同一个按钮 5 次"（熔断生效），强模型这边是"滚 13 次每次不一样"（熔断失效）。

修法：`scroll` 的指纹只保留**方向**（`scroll#down` / `scroll#up`），丢掉幅度。
为什么保留方向：反复滚动本身就是"没有进展"的形态，不需要靠"滚了多远"区分；
但"向下找内容 / 再向上回看"是合理动作，方向得分开。

## 7.3 这条修复我量了代价

| 对象 | 结果 |
|---|---|
| 18 次**基线**轨迹离线复算（旧签名 vs 新签名） | 只有那 **3 次本来就熔断失败**的运行会被命中，熔断点完全相同（18 / 18 / 17）——**没有任何一次通过的运行受影响** |
| 强模型 t06 那次真实轨迹 | 旧规则熔断点 = **从不存在**（所以白烧 20 步）；新规则 = **第 7 步** |

⚠️ 但要把话说清楚：**这条修复把"白烧 13 步"变成"第 7 步明确熔断"，它并没有让 t06 变通过。**
熔断仍然是熔断，只是更早、更便宜、更显形。

这和实验 4 第 ③ 节是同一个教训的第二次出现：
**"加了一个机制" ≠ "解决了那条任务"**。要判断 t06 能不能过，
得在新规则下真跑一次 —— 这一步还没做。

## 7.4 这组数字怎么讲才不算吹

- **`17/18` 不能说成"项目成功率 94%"**：分母是 18 次运行 / 6 个任务，
  而且任务集是自建的玩具站任务（`quotes` / `books.toscrape.com` / `bing`）。
- 真正的信息量在**两个模型之间的差分**上：
  `pass^3 3/6 → 5/6` 说的是"t04、t05 的偶发失败主要来自模型能力"；
  `t06 两边都是 2/3` 说的是"这条两边都栽，更像骨架问题"。
  **没有这个差分，光看 `17/18` 只会得出"换个贵模型就好了"这种没用的结论。**
- **成本栏不能横比**：两次跑的"平均成本 ¥0.02"是用**同一套单价**
  算出来的，而 7B 和 V3.2 的实际单价差很多。要看钱得按各自的价目表重算 ——
  这个数现在只能用来做"同模型内不同版本"的对比。
- 强模型**慢 4 倍**（33.6s → 134.6s），其中 t06 那一次烧了 **576 秒**。
  换模型不是免费的：它是用时间换稳定性，而那条 576 秒恰恰是被骨架漏洞放大的。

## 7.5 下一步

1. **在新规则下重跑 t06**（7B + 强模型各 3 次），看熔断提前到第 7 步后
   模型有没有机会改策略 —— 这是 7.3 那个"还没做"的验证。
2. **把 `--repeat 3` 的基线在新规则下重跑一次**，确认没有回归
   （现在只有离线复算，不是实跑）。
3. **顺手扫一遍别的动作有没有同类洞**：`click` 只看 ref、`type` 不看 text、
   `goto` 看 url —— 目前看只有 `scroll` 把参数写进了指纹，但值得写成一条测试。
